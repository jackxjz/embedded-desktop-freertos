# 基于 ESP32 的简易 FreeRTOS 操作系统

中文 | [English](README.en.md)

本项目为 ESP32-S3 开发板上的 FreeRTOS 桌面模拟器，集成图形用户界面（LVGL）、文件系统、网络同步、电源管理等核心功能，旨在展示嵌入式多任务系统与交互式应用的设计能力。

项目为 **2026 电子科技协会嵌入式组考核** 作品。

---

## 考核要求对照总表

### 关于最大的思路变更

考核 3.1 要求"使用一个输入设备完成光标移动、确认、返回、滚动或等效操作"，3.2.2 要求"接入真实键盘或等效输入设备"。
由于本人开发时间有限，本作品**没有自制鼠标、也没有编写真实键盘驱动**，而是：

- 直接用开发板板载的 **GT911 电容触摸屏**作为唯一输入设备，让 LVGL 自己把触点画成光标 —— 用触摸同时承担"光标移动 + 左键确认"；
- 用**长按（1000ms）**等价替代鼠标右键，用**触摸拖动**等价替代鼠标拖拽；
- 用 **LVGL 软键盘** 承担全部文字输入。

这一取舍在考核文件中被允许（"输入设备形式自定……或等效方案"），同时我也会在下列要求中一一说明。

| 主动熄屏 + 超时熄屏 + 输入唤醒 | ✅ | 桌面有主动"熄屏"按钮；超时息屏可自定义时间 |
| 熄屏唤醒后回到合理状态，不靠重启 | ✅ | 熄屏只切背光，界面对象不销毁，唤醒后停留在原界面 |

### 其他外设

- 无源蜂鸣器（福声科技 FUET-5020）：采用电磁式发声原理，额定电压 3V（工作电压范围 2V~4V），驱动频率 4kHz。贴片式封装（SMD, 5×5×2.2mm），适用于紧凑型嵌入式设计。最大声压级可达 75dB，工作电流 110mA，可在 -20℃ 至 +70℃ 温度范围内稳定工作。用于系统事件提示音、按键反馈及告警通知等场景。

### 主要特性

- **图形界面**：基于 LVGL 构建桌面、应用图标、窗口管理器及软键盘。
- **文件系统**：SPIFFS 支持文件新建、删除、编辑及唯一性校验。
- **账户管理**：本地账户注册/登录，密码错误锁定机制，记住密码（NVS 加密存储）。
- **网络同步**：Wi-Fi 自动连接，NTP 同步时间，断线重连。
- **电源管理**：超时自动息屏 + 主动手动息屏，息屏时间可配置（10/20/30秒）。
- **系统设置**：光标大小调节，参数 NVS 持久化，即时生效。
- **多任务调度**：FreeRTOS 双核任务划分（界面响应、网络后台、电源监控等）。

## 开发日志

所有软件变更将记录于此

### v4.2

#### 改进

- 修复账号管理页刷新列表时可能操作到已销毁对象导致的崩溃：刷新前先把选中状态清空，清空列表时也改成从后往前删，避免"边删边遍历"造成索引错位
- 修复账号列表的内存泄漏：列表项里保存的账号名副本，在刷新和退出时都会正确释放
- 修复关闭文件编辑器时的崩溃：消息框回调改成从事件自身取消息框对象，不再靠父对象层级去猜
- 修复"记住密码"状态与实际存储不一致：登录成功后同步更新记住密码的标志位，让页面状态和存储数据对得上
- 修复光标大小重启后不保持：把光标的创建提前到各个界面初始化之前

### v4.1

#### 新增

- 绘图保存改为后台任务执行：点保存时先快速复制一份画布快照，再交给后台任务慢慢写 Flash，主线程立刻返回，界面不再被卡住
- 保存过程中用标志位挡住重复点击，避免同一次保存被触发多次
- 保存完成回到界面线程弹提示，并再次确认绘图页还在（防止保存途中用户已经退出到桌面）
- 写文件时每扫过几十行主动让出一次 CPU，避免后台写 Flash 把界面任务饿死

#### 改进

- 绘图应用存储格式从文本升级为二进制格式，文件头增加魔数（`DRAW`）与尺寸校验，提升数据可靠性与解析速度
- 采用 8KB 缓冲区批量写入 Flash，减少写入次数，延长 Flash 寿命
- 取消“记住密码”时自动清除 NVS 中已保存的账号凭证，避免隐私残留
- 调整 Wi-Fi 配置结构，优化连接参数管理
- 打开绘图时先校验魔数和画布尺寸，对不上就当旧文件忽略（兼容早期文本格式的残留）

### v4.0

#### 新增

- 全新绘图应用，支持从桌面图标点击进入独立绘图界面
- 基于 LVGL Canvas 实现 480×320 画布，居中显示于屏幕
- 6 色画笔调色板（黑、红、绿、蓝、黄、橙），当前颜色有白边高亮
- 支持触摸滑动连续画线，按下画点、拖动连线、松开停止，绘画手感流畅
- 绘图内容支持保存至 SPIFFS 文件系统，采用非白色像素压缩存储，节省空间
- 应用启动时自动加载上次保存的绘图内容，实现断电恢复
- 完整的页面布局：标题、退出、调色板，以及左下"保存"、右下"清除"

#### 改进

- 画布缓冲区优先使用 PSRAM（8MB），降低内部 RAM 占用，提升大画布处理稳定性
- 内存分配失败时给出友好提示，避免系统崩溃
- 退出绘图应用时自动释放画布缓冲，防止内存泄漏

### v3.3

#### 新增

- 新增无源蜂鸣器硬件适配，提供系统声音反馈能力
- 蜂鸣器用 PWM 驱动，固定频率、靠改变占空比调音量，最大输出限制在一半，避免刺耳

### v1.0

#### 新增

- 工程基于 ESP-IDF 5.2.0 与 SquareLine Studio 1.5.3（LVGL 8.3.11）搭建；界面代码由 SquareLine 生成，手写逻辑集中在界面初始化函数、各控件的事件回调和扩建的界面构建函数里
- 板级支持层拆成三部分：屏幕与触摸驱动、LVGL 适配层（缓冲区、互斥锁、任务、输入设备注册），以及装载分辨率与任务参数的头文件
- 显示采用防撕裂模式 3（LCD 双缓冲 + LVGL 直接模式），帧缓冲放在 PSRAM
- 界面任务固定跑在 CPU1（优先级 2、栈 6KB），主程序留在 CPU0，形成双核分工
- 系统节拍 1000Hz，界面心跳 2ms
- 屏幕支持 0/90/180/270 度旋转，旋转时同步调整触摸的坐标交换与镜像
- 编译期强制检查色深为 16 位且不做字节交换，与 SquareLine 工程设置保持一致

## 故障排除

此部分内容由 AI 详细阐述

### 1：创建文件后系统立刻重启

**现象**：长按桌面空白处 → "新建" → 输入文件名并确认后，**系统立刻重启**；重启后进入桌面，文件实际上已经创建成功（因为崩在刷新路径上）；再次创建仍会重启。

**排查过程**：

串口日志在崩溃前正常打印 `SPIFFS: 文件创建成功: /spiffs/usr_xxx.txt`，紧接着：

```
Guru Meditation Error: Core 1 panic'ed (LoadProhibited)
PC : 0x4200e26b
EXCVADDR: 0x00000010
--- 0x4200e26b: lv_obj_get_user_data at .../core/lv_obj.h:322
--- (inlined by) refresh_file_icons at .../main/lvgl-file/screens/ui_Screen3.c:329
```

`EXCVADDR = 0x10` 是野地址（对 NULL + 0x10 偏移解引用），说明取到的对象指针无效。

**原因分析**：`refresh_file_icons()` 先取 `lv_obj_get_child_cnt()` 得到固定数量 `cnt`，然后**正序** `for (i = 0; i < cnt; i++)` 遍历；循环体内 `lv_obj_del(child)` 会让容器子对象数不断缩短，于是 `lv_obj_get_child()` 的索引逐渐错位，最终取到已释放/无效对象，再对其调用 `lv_obj_get_user_data()` → 解引用野指针 → `LoadProhibited`。崩溃发生在"新建文件成功后刷新桌面"这一唯一路径上，与"创建后必崩、重启后文件还在"的现象完全吻合。

**解决方案**：

1. 改为**倒序**遍历 `for (int32_t i = cnt - 1; i >= 0; i--)`，用有符号 `int32_t` 避免 `i--` 下溢成 `UINT32_MAX` 再次越界；
2. 遍历时跳过两个"虚拟应用图标"（`__settings__`、`__draw__`），否则会把设置/画图图标一并删掉；
3. 删除顺序保持"先 `free_icon_user_data(child)` 释放 `user_data` 动态内存，再 `lv_obj_del(child)`"；
4. 循环结束后统一重置 `selected_file_icon`、`dragging_icon`、`drag_in_progress`、`long_press_handled`、`desktop_press_moved`，再 `load_icon_positions()` 并按新列表重建图标。

**当前状态**：已修复。

### 2：光标大小重启后不保持（滑块位置正确但光标恢复默认）

**现象**：在设置页拖动"光标大小"，光标实时变大/变小，Slider 也停在拖动后的位置；但**重新开机后进入设置页，Slider 仍在上次的位置，光标却恢复成默认的 16×16**。

**原因分析**：`ui_init()` 中先执行了 `ui_Screen5_screen_init()`，之后才创建 `ui_cursor`。而 `ui_Screen5_screen_init()` 内部会调用 `apply_cursor_size(saved_size)` 来"立即应用保存的光标大小"，此时 `ui_cursor` 仍是 `NULL`，函数开头的 `if (ui_cursor == NULL) return;` 让这次调用**静默失效**，随后光标按默认尺寸 16 创建。Slider 之所以看起来正常，是因为它的值是在界面初始化时直接 `lv_slider_set_value()` 写入的，与 `ui_cursor` 无关。

**解决方案**：把 `ui_cursor` 的创建、样式设置、`lv_indev_set_cursor()` 绑定、初始位置**整体前移到所有 `ui_Screen*_screen_init()` 调用之前**，并在 `ui.h` 中补 `extern lv_obj_t * ui_cursor;`。

**当前状态**：已修复。

### 3：熄屏时间重启后不保持（始终回到 10 秒）

**现象**：设置页把熄屏时间改为 20 秒或 30 秒并保存，当时生效；**重启后打印的日志始终是"熄屏时间: 10 秒"**，需要重新进设置页点一次才会恢复成保存值。

**原因分析**：这是一个**初始化顺序**问题。`main.c` 的调用顺序是：

```c
waveshare_esp32_s3_rgb_lcd_init();   // 内部 → lvgl_port_init() → screen_timeout_load()
init_spiffs();                       // SPIFFS 到这里才挂载
...
buzzer_init();                       // 这里才读音量(顺序正确，所以音量能恢复)
```

`lvgl_port_init()` 里调用的 `screen_timeout_load()` 会 `fopen("/spiffs/screen_timeout.txt")`，但此时 SPIFFS **还没挂载**，`fopen` 必然失败，函数返回默认值 `SCREEN_TIMEOUT_DEFAULT`（=10）。而全工程只有设置页（`ui_Screen5.c`）会调用 `lvgl_port_set_screen_timeout()`，桌面和其它界面都不会重新应用保存值，于是熄屏时间在每次开机后都退回 10 秒。

**解决方案**（任选其一）：

1. 把 `init_spiffs()` 提到 `waveshare_esp32_s3_rgb_lcd_init()` **之前**（改 `main.c` 两行顺序，最省事，但要注意 SPIFFS 与 LVGL 没有依赖冲突）；
2. 或在 `init_spiffs()` 之后显式补一次 `lvgl_port_set_screen_timeout(screen_timeout_load());`；
3. 或把 `screen_timeout_load()` 从 `lvgl_port_init()` 内部延迟到 `ui_init()` 阶段执行。

**当前状态**：**未修复**，属于考核 3.2.1"参数修改后需要保存，重新开机后应保持用户最新设置"的**未达标项**，建议优先处理。

### 4：消息框关闭按钮"×"不显示 / 中文乱码（字体子集反复复发）

**现象**：消息框中文能正常显示时，右上角的关闭按钮"×"是空白；把字体改到 `LV_PART_ITEMS` 上之后"×"出来了，但中文又变成乱码。仓库里 `fix(font): embed missing glyph data to prevent garbled text` 这一提交信息**出现了三次**（`2d35adc`、`677d114`、`1240add`），说明这是一个反复复发的问题。

**原因分析**：`lv_msgbox` 由两部分组成——标题/正文 label 属于 `LV_PART_MAIN`，**按钮矩阵（含关闭按钮）属于 `LV_PART_ITEMS`**。工程使用的中文字体 `ui_font_Font1` 是**按需生成的子集字体**，其字符集由 `main/lvgl-file/fonts/ui_font_Font1.c` 文件头的 `--symbols` 参数显式列出（`--bpp 1 --size 20 --font ...simkai.ttf -r 0x20-0x7f --symbols 登录注册成功失败界面...`）。它只包含"命令里列出的汉字 + ASCII 0x20~0x7f"，**既不含 `LV_SYMBOL_CLOSE` 这类符号字形，也不含任何没被列进命令的新文案汉字**。因此：

- 用 `LV_PART_MAIN` 设置 → 中文正常、`×` 缺失；
- 用 `LV_PART_ITEMS` 设置 → 默认字体的 `×` 正常、中文缺失；
- 任何**新加的中文文案**（例如后来加的"重命名""屏幕亮度""清空日志"）只要没重新生成字体，就必然乱码。

**解决方案**：

1. 消息框字体**分三处**设置：`lv_msgbox_get_title()` 与 `lv_msgbox_get_text()` 用 `&ui_font_Font1`；`lv_msgbox_get_btns()` 用 `LV_FONT_DEFAULT`（或 `&lv_font_montserrat_14`，前提是该字体已启用）——**这是 DeepSeek 排查中给出的建议，但当前代码 `main/lvgl-file/ui.c:112` 仍然给 btns 用了 `&ui_font_Font1`**，因此"×"缺失问题理论上仍然存在，属于**未完全落地**项；
2. 每新增一句中文界面文案，就必须**重新生成字体**（在字体转换命令的 `--symbols` 里补上新汉字），否则该文案一定乱码。建议在 README 中把"改文案 → 重生成字体"写成固定流程，避免第四次复发；
3. 顺带提醒：`ui_font_Font1.c` 文件头已经列出了"亮度"二字，但设置页并没有亮度项，说明字体曾经为亮度功能准备过（见第八节建议 4）。

**当前状态**：部分修复（标题/正文已分别设字体；按钮矩阵仍用中文字体，`×` 显示问题待验证）。

### 5：取消勾选"记住密码"后仍会自动回填账号密码

**现象**：先前勾选过"记住密码"并成功登录过一次；之后取消勾选"记住密码"，下一次进入登录页（无论开机还是从桌面返回）**账号和密码依然被自动填入，且复选框又变回勾选状态**。

**原因分析**：`ui_Screen1_screen_init()` 在**每次进入登录页时都会执行**（包括开机首次和从其它界面返回），其中的逻辑是"只要 `read_text_from_nvs("acc"/"pwd")` 成功就回填并 `lv_obj_add_state(ui_jizhu, LV_STATE_CHECKED)`"。而 `ui_event_jizhu` 中的取消分支原先**只把 `is_remeber` 置为 false，并没有删除 NVS 中的键**，旧凭证依然存在，于是下次初始化照旧回填并重新勾选。在初始化里判断 `ui_jizhu` 状态是行不通的——无法区分"用户主动取消"与"从未保存过"。

**解决方案**：在 `ui_event_jizhu` 的 `LV_EVENT_VALUE_CHANGED` 分支中，`is_remeber == false` 时立即调用 `delete_save_account("acc")` 与 `delete_save_account("pwd")`（内部执行 `nvs_erase_key` + `nvs_commit`）。

**补充**：`ui_Screen4.c` 的 `delete_account_from_file()` 也会无条件调用同一对删除，即"删除任意一个账号"都会顺带清掉记住密码的凭证。这一行为是否合理需要确认，如无必要建议改为"仅当被删账号等于已记住的账号时才清"。

**当前状态**：已修复。

### 6：反复进出绘图应用导致内存泄漏与定时器叠加

**现象**：多次"进入绘图 → 退出 → 再进入"后，PSRAM/内部 RAM 持续下降；桌面右上角的时间刷新定时器数量不断增加。

**原因分析**：两处叠加：

1. `ui_Screen6_screen_destroy()` **没有调用 `lv_obj_del(ui_Screen6)`**，只是把 `ui_Screen6` 等指针置 NULL 并 `free(canvas_buf)`。也就是说每次退出绘图页，**整棵 Screen6 对象树（含 Canvas 对象、调色板按钮、`lv_mem_alloc` 出来的颜色 `user_data`）都被留在了 LVGL 的对象堆里**，同时 Canvas 内部仍持有已 `free` 的缓冲区指针（悬空引用）。
2. 绘图页退出流程里调用了 `ui_Screen3_screen_init()`，但 Screen3 在 `ui_init()` 时**已经创建过**。这次调用会**再创建一整块新 Screen3 并覆盖全局指针**，旧 Screen3 及其上的 `time_refresh_timer`、`ui_desktop_kb`（`lv_keyboard_create(lv_layer_top())`）全部丢失引用；于是每进出一次绘图页，就会多一个 1 秒定时器在后台跑、多一个顶层键盘对象堆积。

**解决方案**：

1. `ui_Screen6_screen_destroy()` 内补 `lv_obj_del(ui_Screen6)`（在 `free(canvas_buf)` **之前**删对象，避免悬空 buffer 被绘制）；
2. 退出流程改为 `_ui_screen_change(&ui_Screen3, LV_SCR_LOAD_ANIM_FADE_ON, 200, 0, &ui_Screen3_screen_init)` 的形式 —— 由于 `_ui_screen_change()` 内部有 `if (*target == NULL) target_init();` 判断，Screen3 已存在时**不会重复 init**，正好符合原意；
3. 或者干脆不销毁 Screen6，改为与 Screen1~5 一样常驻（代价是约 300KB PSRAM，需权衡）。

**当前状态**：**未修复**，直接影响考核 3.2.3 的"连续打开和退出应用 30 次"测试项。
